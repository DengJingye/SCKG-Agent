# plan_v1/G1：执行准备阶段的代码观察记录

此前结果清单中的 `code_sha` 总是缺失。现在，获得授权并进入分析 worker 的新尝试会在准备数据和调用科学执行器之前，采集一次 `analysis-code-provenance-v1` 记录，保存在已有不可变 `analysis_preparation` 收据中。最终分析收据保存其摘要；v2 恢复范围继续绑定整个 preparation，没有第二套任务状态或新队列。

记录包含：

- 当时观察到的 Git HEAD，以及 tracked/index 是否有改动。Git 不可用、超时、不是仓库根目录、版本在检查期间变化或元数据不完整均保留明确原因。
- `workbench_app.py` 和 `sckg_workbench/`、`core/`、`engine/`、`execution/` 下实际存在的 `.py` 文件 SHA256 清单及其整体指纹。范围内未跟踪或被 Git 忽略的 Python 文件也会计入；跳过 `__pycache__`。
- 采集时间、文件数量、字节数、范围和缺失原因。连续两次清单必须一致；符号链接、非普通文件、缺失文件或超出限制不会产生部分成功指纹。

边界固定为 512 个源码文件、4,096 个目录条目、8 MiB 源码，两次源码遍历共 2 秒；每条 Git 命令最多 1 秒，共四条。Git 仅查询元数据，不更新索引，不读取用户全局 Git 配置，不安装依赖。采集失败只降低溯源完整性，不自动重试科学执行或改变其参数。

`code_sha` 的含义是准备前观察到的 Git HEAD，包括脏工作区时的基准提交；必须结合 `code_provenance.source_hash` 和 `git.tracked_dirty` 阅读。它不保证所加载字节码与磁盘一致，不覆盖第三方包、非 Python 配置、范围外源码或采集后的变化。`loaded_execution_image_verified` 和 `reproduction_complete` 均保持 false。现有合同、环境、notebook 指纹仍由原结果清单提供；此功能不把它们替换成完整工具注册表身份，也不补造父对话的模型或知识库身份。

导出只读取保存的记录，验证其结构及与最终收据的摘要绑定。公开 ZIP 包含摘要、计数和限定字段，省略源码文件清单及本地绝对路径。代码后来变化或程序重启不改写历史快照。旧记录仍可读取，其 ZIP 结构与缺失语义不变；新记录损坏或只剩半份绑定时不导出为成功结果。
