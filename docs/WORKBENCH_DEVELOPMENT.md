# 工作台开发与验收路线

状态日期：2026-10-18。本文描述公开源码的开发方向、已有观察及继续推进的关卡。具体能力以对应提交和运行收据为准；时间窗口是工作量目标，不是交付日期或效果保证。

## 1. 要交付什么

项目同时追求四项成果，各自保留验收证据：

| 目标 | 应有成果 | 不能作为完成依据 |
| --- | --- | --- |
| 求职作品 | 可启动源码、清晰架构、真实演示、测试与失败修复记录、可核查的资源和成本 | 只有界面截图、角色数量、计划中的指标；项目也不能保证录用 |
| 完整产品 | 连续交流、来源追溯、任务进度、受限工具执行、独立产物验收、取消与恢复 | 单轮回复、生成但未执行的代码、后台进程仍在运行 |
| 知识库的科学价值 | 在明确任务范围内减少关键事实错误和条件遗漏，改善决策或有效科学产物 | 文献数量、回答长度、引用能打开、工程测试全部通过 |
| 外部系统比较 | 包含 Genpilot 的原生访问资格核验、共同任务结果、成本与失败分母 | 公开仓库可访问、调用一个基础模型接口、同一生成器的包装消融 |

短期先把一个受限任务交付完整，再扩大任务族。领域流程知识用于解释“何时适用、还缺什么、如何执行与验收”；真实执行能力必须另有工具、环境和验证合同。

## 2. 当前状态及其边界

下表是已有本地观察的公开摘要，不是本仓库在所有机器上的保证，也不要求公开私人工作区或原始模型请求。

| 能力 | 已有实现或实际观察 | 尚未通过的门槛 |
| --- | --- | --- |
| 工作台与主 agent | 已有连续对话、任务记录、模型网关、有界工具循环、数据画像和产物展示 | 完整单细胞多组学产品尚未完成；不同任务族需要分别取得端到端资格 |
| 受控分析闭环 | 限定 macOS/Scrublet 路径已有真实小数据执行、一次有界修复和独立产物验收证据 | 不能推广为其他方法、全部运行环境或稳定成功率，更不是知识库增益证据 |
| 流程输入检查 | 已接入 velocity、表达相似性 pseudotime、实验 lineage、CellPhoneDB 式通讯、参考映射五条开发路线，包含八项局部输入要求 | 各路线均保留 `requirements_complete=false`；不是完整科学适用条件或通用执行器 |

| 公开源码阶段验证 | 初次发布 **136 项通过**；本轮显式缺失合同修复后，隔离分支 **164 项通过**。新建合成工作区的七页、来源选择及三态表单已有完整 AppTest 证据 | 详见 `WORKBENCH_VALIDATION.md`；不同版本分别报告，不替代 provider 或科学终点评测 |
| 实际宿主 UI | 安装宿主上的 **Streamlit 1.56.0 完整工作台 AppTest** 通过，覆盖已存 turn 展示、两次刷新无新调用、来源/跨度显示及模式切换 | 使用明确的脚本化内存模型 transport；不是新 provider 调用、浏览器截图或真实 M0 语义验收 |
| 首次真实流程对话 M0 | 实际仅 **1 次 provider 调用、5,544 个 provider 报告 tokens**；第一次动作选择了四条允许路线 | 四路线完整后续上下文超过原输入预算，第二次调用尚未发出即停止；**未完成该自然语言流程端到端旅程，没有科学增益结论** |
| 容量修复后的真实调用 | 第二包4次调用：W01两次调用完成，W02最终字段合同失败。显式合同修复后第三包第一请求返回HTTP400，无回答，后两题未启动 | 164项工程测试及旧真实记录UI通过；新合同尚无真实完成资格。HTTP400具体字段原因未知；远端用量未知，停止付费重试 |
| 知识质量与效用 | 有来源绑定、开发候选、流程补齐和公开开发对照材料；已有对照允许零收益或退化 | 独立领域金标、完整确认评测、知识问答科学优势、Genpilot 原生性能比较仍未完成 |
| 公开交付 | 公开代码、工程夹具、入口与文档可逐步验证和发布 | 科学 runtime 包、论文全文、私人账本与真实数据不随源码发布；整体跨机器交付另行验收 |

`unknown`、`reported_unmet` 和 `reported_met` 分别表示未说明、用户报告缺少、用户报告具备。`reported_met` 最多支持针对已列要求的条件计划；不证明全部科学前提成立，也不意味着本机可执行。当前这些局部检查保留科学判断 `no_claim` 和未绑定的执行状态。

例如，用户明确没有 unspliced 时，可阻断依赖它的 velocity 路线，同时保留表达相似性 pseudotime 的条件方案。不能把某一路线被阻断解释为所有分析都不可行，也不能从文件名、layer 名或普通 metadata 推断真实测量内容。

## 3. 默认架构：一个主 agent，明确的工具与验证边界

主路径使用 `workbench_app.py`，复用现有服务，不另建聊天系统、任务队列或证据库。

| 层 | 职责 | 关键边界 |
| --- | --- | --- |
| 交互与会话 | 连续交流、证据查看、任务状态、取消、结果读取 | 刷新和页面切换不发请求；只读追问不得重复拟合 |
| 任务控制与 harness | Ledger、队列、检查点、幂等、预算、超时、取消、上下文构建与 trace | 外部请求结果未知时先核对，不自动重发；监督器不等于操作系统沙箱 |
| 主 agent | 根据当前任务和数据状态选择检索、追问或工具操作 | 模型提出动作，控制层检查结构、权限、预算与完成条件 |
| 来源与知识服务 | 来源修订、候选隔离、检索、精确引用、条件与冲突 | 解析完成不证明全文齐全；引用精确不证明语义支持正确 |
| Typed tools 与领域技能 | 声明输入、状态、版本、参数、依赖、输出和允许动作 | 讨论可行、当前输入可行、本机可执行分别判断 |
| 科学 worker | 在已核环境中执行受限操作，原始数据只读，输出到新目录 | 参数预先冻结，资源有界；不得为救一个结果静默扩大预算 |
| 独立 validators | 读取实际文件、输入身份、轴、数值、版本与运行证据 | 模型宣布成功不能代替验收；工程完成与科学质量分别报告 |

优先复用 `sckg_workbench/` 中的聊天、任务、模型服务、流程输入与 agent loop，以及现有 ToolContract、产物注册和验收组件。发布验收脚本是评估入口，不应被描述成已经接通的产品 agent 循环。

产品中的多 agent 是消融候选，默认不部署常驻“专家人格”。先比较单主 agent、单主 agent 加独立验证器、主 agent 加按需专家：固定任务、来源、工具权限及总调用/token 额度，测正确性、遗漏、失败率、成本和延迟。只有出现可独立分解、输出可验收且同预算有收益的任务，才加入额外分支；开发阶段的并行代码审查不等于产品多 agent 已有收益。

## 4. 知识包应保留的最小合同

知识核心是有来源、带条件、能连接实际动作的流程声明。建议保留以下字段，并区分来源直接断言、跨来源综合和本地工程策略：

| 内容 | 最低要求 |
| --- | --- |
| 任务与身份 | assay、方法、实现/工具版本、任务终点及适用范围 |
| 输入与前提 | raw/log/normalized 状态、单位、轴、必需/可选输入、默认与空值语义、未知项 |
| 参数与步骤 | 作者默认、示例选择、实验实际值分开；明确依赖、分支、替代路线与失败恢复 |
| 输出与验收 | 产物类型、身份和轴；一般完整性、方法特异检查及独立科学终点分开 |
| 来源与治理 | 原件身份、修订、精确位置、作品依赖组、使用资格、核验者真实身份 |

先查现有材料的覆盖与遗漏，再补直接影响决策的权威来源。完整记录某段已关联、部分覆盖或跳过的原因；`linked` 只说明建立了关联，不代表语义齐全。候选保持隔离，AI 核查不得填写为人类专家审核，也不得自动进入正式推荐路径。

长读、短读、空间等名称只是导航。实验设计、模态组合、表示状态、物种/坐标、任务终点和资源都会产生不同分支，不能把“每类放几篇经典论文”视为领域覆盖完成。

### `shared_text_v2` 与容量门

重复科学字符串可集中存放、由显式引用恢复；必须逐项重建并核对全部科学内容。条件、未知项、来源属性和引文不能为了省空间被删除。旧表示的只读重放继续保留，不能追改旧回答或旧评分。

调用前检查完整 payload、允许的路线组合、必要反馈及输出预留。当前容量检查使用 **UTF-8 字节代理，不是 tokenizer 计数，也不是 provider 报告 tokens**。预检合格后仍须执行模型网关的实际输入门；任意长用户输入和任意未来反馈没有自动合格保证。超容量应在调用前停止并保留原因，不能截掉科学限定或暗增预算。

## 5. 时间窗口与验收关卡

短期 **7–14 天**、中期 **3–4 周**、长期 **6–8 周及后续**是工作量目标。按关卡前进；外部访问、领域标注、科学环境和确认样本可能改变所需时间。任何改动门槛都记录新版本与理由，不能看到结果后降低标准。

| 阶段 | 交付产物 | 测量与必须通过的测试 | 不通过时停止什么 |
| --- | --- | --- | --- |
| G0：运行基线；短期持续维护 | 唯一主入口、依赖/版本记录、串行自动验收、故障分类和资源记录 | 必需导入及关键服务实际运行；有效 JUnit；零失败/错误且非全跳过；超时、资源和进程清理可观察 | 停止付费批量评测，先修工程或环境 |
| G1：完整受限旅程；短期重点 | 连续对话、来源回答、一个真实小数据技能、产物报告、取消/恢复演示 | 至少十个预声明场景，覆盖正常、缺输入、不支持、坏产物、修复、取消、恢复、重复请求；至少一份真实小数据产物通过独立验收；新增流程对话须重新取得真实 M0 资格 | 停止扩大该能力的用户承诺；定位模型、接口、容量、环境、算法或验收层后窄修 |
| G2：知识可用；短中期 | 两个深入支持任务族的流程包、版本化检索、主张—证据标注及条件传递测试 | 引用/修订身份完整；关键条件从检索到工具合同不丢失；对独立标注报告抽取与语义 precision/recall 及区间；正例和有效替代不能被全拒绝 | 停止把候选称为可信完整知识，补内容或表示；不靠堆论文掩盖缺口 |
| G3：开发效用；中期重点 | 两至三个深入任务族、知识消融、至少两种任务匹配外部系统的实际首批比较 | 至少十二个开发依赖组；预冻评分与预算；公开所有尝试、失败和未评分项；评分器正反例及元数据隐藏检查通过 | 停止付费扩批或“有优势”表述；保留零收益、退化及具体错误，修复对应机制 |
| G4：确认优势；长期 | 独立确认分区、预注册主指标、实际样本量、配对效应与区间 | 以开发方差和实用差异确定 N；通常先规划 60–120 个工作族组，最终数量由功效分析决定；主效应满足预定目标且严重错误不增加 | 停止科学优势宣称；结果不支持胜出就报告有限、零差异或退化 |
| G5：交付与作品；各阶段推进、长期完成 | 可安装启动、干净环境验收、3–5 分钟真实演示、公开脱敏结果与恢复说明 | 新空间复现；安装/资源边界可查；每项简历指标能回链到代码和运行；公开文件通过许可与隐私检查 | 停止发布不合格包或不可核查指标，修复复现与发布材料 |

当前 G0 和限定 macOS/Scrublet 的 G1 已有工程通过证据；这不覆盖新增流程对话，也不意味着整个产品完成。G2 语义质量、完整 G3、G4 和整体 G5 尚未完成。工程产品可以继续交付，科学优势须经独立关卡确认。

### 原生资格停止边界（历史家族，仍适用）

1. 保留两包原始失败。第二包的问题是输出合同未将跨字段规则完整表达给模型；修复版本为 `explicit_missing_v2`，不放宽本地校验、不重写原输出。
2. 当前合同的120项路线/历史容量检查已通过，最大完整包络60861低于65536。原三场景新包第一请求HTTP400即停止；原W01仍是旧版本成功，不拼成四题成功。先核验实际gateway的wire格式能力，并与完整本地校验分开；没有取得原因前不猜字段、不自动降级或重试。
3. 家族实际已用6次请求、169252代理预留；已知报告29751tokens，另1次用量未知。总顶仍为12次/442368，数学余额不代表可继续调用；未知结果先核对，三个已关闭包不重开。
4. 两个任务族的来源覆盖、知识语义标注、评分合同和既有可用路径演示可继续独立推进。接口资格恢复后再做付费知识对照与外部原生比较；不能用离线通过代替真实结果，也不能用字段修复代替科学语义改进。

## 6. 三条评测轨与比较设计

| 轨道 | 核心测量 | 同时报告 |
| --- | --- | --- |
| 领域问答 | 主张正确性、关键条件遗漏、方法适用性与限制 | 引用支持/覆盖、拒答与追问质量、成本、延迟 |
| 流程决策 | 输入状态、必需前提、允许替代、范围、依赖与验证策略 | 当前输入可行性、本机执行资格、未知和额外数据需求 |
| 真实分析 | 独立有效产物及预先声明的科学终点 | 原生完成率、全尝试成功率、修复次数、资源、成本、未完成原因 |

科学结论需要对应终点：工程检查负责文件和运行身份，开发 AI 可诊断语义，独立领域审阅用于校准和确认。没有领域专家金标时仍可继续自动化开发，但必须准确标注评审身份和证据级别。测试数量、机械评分有效率、作者参考分析匹配比例都不能直接称为科学正确率。

### 知识消融

固定主 agent、模型、任务和工具，对比 B 无额外知识、F 同来源同事实平面材料、S 同事实结构化流程，另列实际检索方案。逐项核对 F/S 科学事实、条件、未知和引用等价；内容增量另开单变量比较。格式、来源支持、科学决策和真实执行分别评分。

按作品、研究和数据依赖组划分开发、校准、确认；同论文、教程、仓库和同数据重处理不能伪作独立样本。已暴露题目留在开发分区。冻结 task、数据划分、科学 seed、模型实际返回版本、提示、temperature/reasoning、工具权限、预算、输出及评分版本。`temperature=0` 不保证完全重复，同题重跑也不是新的生物样本。

保留所有尝试和失败分母。格式不合格保持未评分并计入产品失败；有有效产物但未完整结束的运行可评分，同时保留未完成标签。不能只挑成功或最好的一次，也不能在不同有效题目分母间直接相减宣称提升。

### Genpilot 与其他外部系统

Genpilot 原生比较单列轨道，不以调用 `dcs_llm` 或复用公开 harness 代替完整产品。先核验实际访问权限、专家内容范围、原生会话创建/发送/导出/取消、可用工具、成本与任务记录，再选共同支持的任务。当前这些原生访问与计费资格仍未完整验证，没有 Genpilot 性能成绩；公开代码存在也不能证明同行评审发表或产品效果。

先完成两种实际可运行且任务匹配系统的原生比较，再扩大候选。文献问答与科学执行分轨；原生产品配置比较和同模型宿主比较分表。不可访问列 `blocked`，任务不支持列 `unsupported`，不伪造分数，也不让某一外部系统阻断内部工程与知识建设。

## 7. 小步开发、验证和 GitHub 发布

每个小功能按以下顺序推进，避免一次大改后才发现无法复现：

1. 读现有代码和合同，写清用户可见变化、失败条件与影响文件；复用现有实现。
2. 做最小改动，先跑相关离线正反例和一条必要用户旅程，验证实际日志/产物。
3. 在隔离分支或 worktree 核验相同源码、测试和启动路径，记录提交与依赖版本；不能把主工作区历史日志当隔离分支结果。
4. 检查待发布差异、来源许可、凭据和数据边界。通过后将该小功能上传 GitHub，附变更、验证、已知限制及失败记录；GitHub 上传不等于科学资格通过。
5. 新故障或能力变化才扩大必要回归。失败保留原件，修复新增版本；不覆盖旧预测、评分或重要结果。
