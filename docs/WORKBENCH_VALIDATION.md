## 本阶段修复及保留的失败

1. 首次隔离测试为134通过、1失败：监督器测试夹具引用未发布的旧 CLI 测试文件。将该夹具改为实际发布的测试路径后，135例通过；后续加来源选择回归，最终136例通过。原失败未改写成成功。
2. 首次完整界面探针通过七页和候选展示，随后在第三次来源选择失败。真实原因是来源选择框没有稳定 key，并使用随上次选择改变的默认 index，后续选择会被重置。修复 widget 身份后，组件回归和新建工作区的完整探针均通过；原失败保留。
3. 较早的真实 M0 开发旅程只进行了1次 provider 调用、报告5,544 tokens。模型选了4条允许路线，完整反馈超出原输入容量，第二次调用之前停止；其余问题未运行。该轮仍是失败/未完成，未做科学补分。

第三项推动了可逆 `shared_text_v2` 与完整上下文容量前置检查。固定首动作夹具在同一构造层的输入代理从57,541降至48,042字节，约减少16.5%；保留全部科学命题、属性、条件、未知和引文。这个数字不是实际 provider token 节省、普遍延迟收益或科学提升。修复后完整真实模型旅程尚未重新验收。
