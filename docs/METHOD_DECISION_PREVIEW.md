# 方法配置与适用条件：开发预览

这个功能把已保留的流程知识条件接入可检查的决策：用户明确报告输入和配置，系统返回缺信息、冲突、阻塞或条件计划，并附来源。它不读取当前科学矩阵，不拟合、不调用模型，不授权执行。

## 已连接的内容

私有研究克隆使用实际8条注释候选、16项属性、14处锚点，形成8条有限规则。CellTypist自训练与联合嵌入reference label transfer分别建路线；训练知识不能冒充另一方法的必要前提。来源仍为开发候选，未做人审或正式推荐。公开仓库提供明确虚构的工程演示，避免再分发研究台账或论文全文。

| 触发情形 | 预期行为 |
| --- | --- |
| 输入或开关尚未说明 | 返回所缺字段，未知不等同明确没有 |
| 关闭监督特征选择 | 不追问top_genes和过滤后基因数 |
| 开启选择，过滤后基因数不大于top_genes | 阻塞对应训练配置，独立替代路线单独判断 |
| balance选项不满足SGD与mini-batch双条件 | 标记该选项不适用，不据此否定整个方法 |
| 稀疏输入不减均值 | 显示来源记载的内存与表现取舍，不伪造必须约束 |
| 输入布尔声明与具体配置结果相反 | 同时保留两份报告，要求澄清，不挑有利者覆盖 |
| 研究者比较协议不满足 | 在独立协议结果阻塞该实验，不写成作者方法禁令 |
| 来源暂停、输入或目录改变 | 隐藏旧结果，重新核查有效来源与当前报告 |

过滤后基因数指去零表达基因后、监督选择前的轴，不能从文件名或原始基因轴推断。文档快照版本、固定源码版本及当前环境测量分别记录。只有条件计划状态时，完整科学适用性仍未建立。

## 最小代码合同

- `workflow_methods.py`：严格类型的独立方法目录、有限条件表达式及只读评估；复用现有来源治理和输入检查，不另建知识库或队列。
- `workflow_methods_ui.py`：仅在显式配置目录时展示；条件字段显隐、用户报告冲突、完整来源与独立协议显示。
- v1输入/自然语言目录继续使用原active pointer；新目录通过record ID与hash绑定自己的base，不改变旧聊天合同。
- 报告以profile、目录、来源与治理身份计算指纹；结果不是人工审核、数据测量或执行许可。普通工作区没有配置时不出现这项预览。
- 引文正文使用Streamlit文字显示规则；技术来源记录保留原始引文、换行、锚点和哈希。显示空白规范化不改原始证据。

## 无API演示

先使用README中的合格既有环境；目录必须新建或完全为空：

```sh
python -I -B scripts/bootstrap_method_demo.py --workspace "$HOME/sckg-method-demo01"
SCKG_WORKBENCH_HOME="$HOME/sckg-method-demo01" python -m streamlit run workbench_app.py --server.address 127.0.0.1
```

打开“知识库”→“方法配置与适用条件（开发预览）”，同时选择两条SYNTHETIC路线。报告counts具备，打开虚构特征选择，两个数均填300，检查trainer阻塞、counts-only替代保留条件计划；把过滤后数量改为301或关闭选择，重新检查。所有方法、条件和示例均为虚构，不能用于真实科学决策。演示不创建模型连接；原三路线演示及其文件保持可用。初始化失败保留部分新目录，修复原因后使用另一个新目录。

## 本阶段验收与下一关

```sh
python -I -B scripts/verify_annotation_stage.py --output ./annotation-validation01
```

复用120秒/1.5GiB进程树监督，单线程，输出目录create-only。实际宿主相关179项测试、16个假设报告和真实来源完整页面AppTest通过，数字见[阶段记录](WORKBENCH_VALIDATION.md#来源条件接入方法配置)。两次探针失败均保留并解释；不是新原生模型或科学评测。

下阶段仅补已定位的预测分数源码候选，保留校准未知；再把开发条件连到预冻工具合同，逐项检查泄漏边界、版本与真实产物。远程接口资格另行修复。取得原生资格后才运行固定同事实知识消融，再安排共同任务的外部agent比较，包含Genpilot。每步失败定位到对应层，不通过则不扩大能力承诺。
