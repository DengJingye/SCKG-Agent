# plan_v1/G1：结果摘要与复现清单导出

“运行结果”中的已完成 Scrublet 预览现在提供“下载结果摘要与复现清单（ZIP）”。原有逐文件下载继续保留。导出重新走同一条结果校验链：当前任务、尝试次数、运行身份、原数据、预览数据、notebook、保存的结果与 sidecar、参数和结果表均须匹配；取消、失败、状态不明、旧尝试及损坏产物不能导出为成功结果。

ZIP 包含三个固定文件：

- `result_summary.json`：细胞数量、预测双细胞数量/比例、已记录参数、来源声明及工程预览限制；不含逐细胞标识。
- `manifest.json`：任务/尝试/运行身份、seed、参数、数据/环境/合同/notebook 指纹、原产物哈希、分析任务自身的预算与用量、摘要文件哈希。
- `SHA256SUMS`：上述两个文件的 SHA256，针对实际下载字节计算。校验值用于发现内容变化，不是数字签名。

这是摘要与已记录溯源的导出，不是可独立执行的复现环境。原始输入、逐细胞结果、环境和可执行 notebook 不包含在 ZIP 中。历史分析收据未记录的 `parent_run_id`、`code_sha`、模型实际身份/配置、prompt、corpus、index 与完整 tool registry 身份明确为 null，并在 `missing_provenance` 中写明原因。新执行准备阶段会保存[代码观察记录](PLAN_V1_G1_CODE_PROVENANCE.md)；只有确实保存过该记录的结果才导出相应字段。不会拿当前工作区版本冒充历史执行版本；`reproduction_complete` 保持 false。分析任务的零模型预算不能解释为父级对话没有模型费用。

所有结果仍是 `preview_engineering_only`；来源仍为调用方声明且未独立核验。导出不执行模型/科学工具，不写台账，不修改历史收据，不授予科学资格。相同收据重复导出、重新打开工作区后导出得到相同 ZIP 字节。下载表示生成时已验证的快照；已下载文件不会因源数据后来变化而自动撤回，重新打开页面会重新验证。

## 验证范围

`tests/test_workbench_result_export.py` 使用现有合成收据 fixture 和真实存储/校验服务，验证实际 ZIP 内容及文件哈希、缺失信息、重复/重入无副作用、源数据/产物损坏、取消晚结果、身份不匹配、读取中终态变化和真实 AppTest 下载组件。它不运行 Scrublet，不将合成收据当作科学执行。

AppTest 的组件验证与浏览器下载证据分别记录。当前导出补齐 G1 第10条旅程的一部分；完整 G1 仍需10条旅程、真实科学小样本执行及其他故障合同的独立证据。G0 的人工审查状态和历史验收结果不在本次更改。

开发验证（使用已安装的工作台开发依赖）：

```sh
python -B -m pytest -q -p no:cacheprovider tests/test_workbench_result_export.py
```

完整离线回归继续由 `scripts/verify_g0.py` 自动选择所有 `test_workbench_*.py`；各次运行保存新目录，不覆盖以前的结果。
