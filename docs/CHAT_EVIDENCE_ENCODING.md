# 普通聊天证据包：无损共享编码

状态日期：2026-10-18。本阶段修复普通主聊天的输入容量问题。完整原包可以交付模型之前，不能检验知识是否改善回答；容量资格通过也不代表回答或分析任务完成。

## 已实现的合同

`ChatService.send` / `submit_send` 可显式传入 `evidence_encoding`：

| 选择 | 行为 |
| --- | --- |
| 不传参数 | 保持旧 `literal_v1` 消息、请求字段与哈希；历史请求不补字段、不迁移 |
| `literal_v1` | 原文展开；显式选择进入不可变请求哈希 |
| `shared_text_v1` | 普通聊天中，仅将出站 metadata JSON 的 `evidence_packages` 编码为可逆封装；显式选择进入不可变请求哈希 |

新 UI 的普通聊天提交显式选择 `shared_text_v1`，结合知识库开关的 B/R 两侧均携带相同编码标记与说明。深入查证、开发流程、分析执行和已有结果读取不带该参数；API 将共享编码与这些模式组合时前置拒绝，不自动回退。同一 request ID 改变编码会冲突；旧请求的刷新或重放不新增模型调用。

实现在 `sckg_workbench/evidence_wire.py`，当前产品共53个模块。它独立于流程对话的 `shared_text_v2`；后者的字段投影不能直接替代完整普通聊天证据包。

封装结构为：

```json
{
  "schema_version": "evidence-shared-text-v1",
  "text_table": {"T1": "完整且重复出现的长字符串"},
  "data": [{"claim": {"proposition": {"$text": "T1"}}}]
}
```

上例仅说明结构。实际只共享至少160字符、重复出现的字符串；不改写或摘要，不截断条件、未知、否定和引文。键、数组顺序和全部值可完整还原；candidate/source/quote 定位 ID、哈希、URL、路径及定位子树保持原值。`T1` 仅是字符串引用，不是来源或引用编号。

原包中恰好只有 `$text` 或 `$object` 键的对象递归转义为 `{"$object":[["原键",编码值]]}`。解码时重建原对象一次，不将重建结果再次当标记；字符串中看似 JSON 的内容仍是字符串。严格本地解码拒绝未知引用、未使用或只使用一次的表项、非法转义、非字符串对象键和非有限数值。编码器自身先核对 canonical JSON 往返相等，验证不依赖模型执行解码。

服务端保存的 `evidence_package` / `evidence_packages` 仍是完整原包。来源暂停、用途资格、历史证据及展示校验继续使用原包；模型可见投影不反向替代它。检索查询、前五条及顺序、发布版本、预算和知识内容均未修改。

## 实际容量资格

对同四道已暴露开发题，复用真实 `KnowledgeService.search` 和 `ChatService._prepare_context`，两组每题空历史。B 关闭知识检索，R 保留原 release 的五条命中；四个 R 包共20次命中，完整单元逐字段相同且解码后等于原包。

| 固定题号 | B 原 literal | B 新 shared | R 原 literal | R 新 shared |
| --- | ---: | ---: | ---: | ---: |
| row4 | 4,732 | 5,606 | 30,762 | 26,919 |
| row5 | 4,766 | 5,640 | 26,749 | 25,012 |

| row7 | 4,838 | 5,712 | 准备失败；完整重建36,152 | 31,132 |

原 row7 的实际准备失败，36,152 是完整重建的容量代理，不能称旧网关请求或已成功准备。前三个 R 的原代理来自实际准备。新共享编码增加空包说明开销，因此 B 更大；不能据此承诺所有输入都缩小。

固定四题 **R 输入容量准备通过3/4→4/4**，新 B/R 八个输入均准备通过。这不表示任务完成率提高，也不表示知识增益、问答正确率或模型对编码的理解已验证。零 API 资格实际耗时6.949秒，采样进程树峰值194,543,616字节；0拟合、新环境、生产写入或人审。

## 检索相关性仍是独立问题

`retrieval_relevance_review01.json` 对未改变的20次命中作静态 AI 描述：6次背景、12次不相关、1次明显有用、1次不足判断，涉及13个不同候选。这是公开评审身份的开发诊断，既非领域专家金标，也非验证后的 precision 或独立生物学样本。容量修复没有修复排序；不能将后续原命中 B/R 对照描述为高质量流程卡的效用证明。
